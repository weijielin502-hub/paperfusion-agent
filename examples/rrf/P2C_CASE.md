# Paper2Code standalone smoke test

This is a separate DeepSeek run of the vendored Paper2Code pipeline. Its input was the structured [RRF method and project note](paper.json), not the paper's full PDF. The note combines the public RRF formula with explicit rules for a synthetic search application. It is therefore a pipeline and code-generation check, **not** a reproduction of the original paper's experiments.

Planning, configuration extraction, Analyzer, and Coding all completed. The checked adapter confirmed the expected artifacts and files. The generated standalone repository is frozen in [p2c-generated/](p2c-generated/). It has a different `SearchApp` interface from the existing application in the main [integration case](CASE.md); PaperFusion uses generated code as reference material, not a drop-in patch.

The first run of the generated repository's 230 self-authored tests had one failure: `test_scores_accepts_generator` expected the second item in a two-item ranking to have rank 3. The bounded debugger changed that expected score to rank 2, matching the input and the RRF formula. All **230 generated tests then passed**. These tests were generated by the same pipeline and are not independent proof of correctness. The separate PaperFusion integration case passed eight controller-owned Docker acceptance tests.

The live run's full model traces and logs stay under ignored `runs/p2c-smoke/` because they contain long prompts and local environment details. The committed snapshot contains the code and tests after the exact debugger correction. The staged outputs were inspected for credentials and private project paths before packaging.

To run the generated tests from the repository root:

```powershell
cd examples/rrf/p2c-generated
python -m pytest -q
```
