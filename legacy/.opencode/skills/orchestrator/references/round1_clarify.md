# Phase 1c 参考：需求分析必问清单

Orchestrator Phase 1c 自动分析时参考此清单。不需要逐条追问用户，而是从已有信息自动提取。

---

## 必问清单（自动提取规则）

### 1. 项目范围

| 问题 | 提取来源 |
|------|---------|
| 项目叫什么？核心功能？ | artifacts/project_context.md |
| 当前已有的代码/模块？ | 目录扫描 + 关键文件分析 |
| 最终产物形式？ | 用户 goal 描述 + 现有入口文件类型 |

### 2. 论文定位

| 问题 | 提取来源 |
|------|---------|
| 论文标题/链接 | 用户提供的 paper_path |
| 具体使用哪个技术点 | P2C planning_artifacts 中的核心方法部分 |
| 在项目解决什么业务问题 | 用户 goal + 项目现有模块的 gap 分析 |

### 3. 复现深度

| 默认决策 | 条件 |
|---------|------|
| **B. 理解核心逻辑，按项目改造** | 默认 |
| A. 完整复现 | 用户 goal 中出现"完整复现""一模一样"等词 |
| C. 只参考思想 | 用户 goal 中出现"参考""借鉴""思想"等词 |

关键模块严格度：
- 核心算法（论文创新点）：严格按论文
- 辅助模块（数据处理、配置）：按项目改造

### 4. 技术约束

| 问题 | 提取来源 |
|------|---------|
| 技术栈偏好 | requirements.txt / pyproject.toml / package.json |
| 接口风格 | 扫描现有代码的 base class / config 格式 |
| 内部 SDK | 项目中的 lib/ 或 vendor/ 目录 |

---

## 产出格式

自动分析完成后产出设计摘要（artifacts/design_summary.md）：

``markdown
# 设计摘要

## 项目
- 名称: {项目名称}
- 简介: {一句话描述}
- 技术栈: {Python X.X, PyTorch, ...}

## 目标论文
- 标题: {论文标题}
- 核心技术: {具体方法/算法}
- 解决业务问题: {一句话}

## 复现策略
- 总体深度: {A/B/C}
- 关键模块及严格度:
  - {模块A}: {严格按论文 / 改造 / 参考思想}
  - {模块B}: ...

## 技术约束
- 接口风格: {...}
- 复用组件: {...}
- 依赖版本: {...}
``

展示给用户 -> 一次性确认后进入 Phase 2。
